### Sample Outline 2: CLUSTER 4 — "Fixing the Infinite Loop: Multi-Year Renewal Automation That Actually Works"

**H1: Fixing the Infinite Loop: Multi-Year Renewal Automation That Actually Works**

**H2: The Problem — Why Your Renewal Workflow Creates One Deal and Stops**
- Scenario: Workflow triggers on "Closed Won in Renewal Pipeline" to create next year's renewal
- HubSpot's built-in infinite loop protection blocks re-enrollment
- The workflow silently skips — no error, no notification, just missing deals
- Why this is the #1 reported renewal automation issue (cite: HubSpot Community threads, Ideas forum votes)
- Quote from community: "a pretty wild hack to get around a HubSpot limitation out of the box"

**H2: Understanding HubSpot's Re-Enrollment Rules**
- How enrollment works: once per contact/deal by default
- Re-enrollment options and their limitations
- Why "allow re-enrollment" doesn't fully solve it for renewal chains
- The 31-minute delay requirement for re-enrollment to register
- Screenshot: workflow re-enrollment settings

**H2: Solution 1 — The Dual-Workflow Pattern (Native HubSpot)**
- Create Workflow A: triggers on Closed Won for "odd" renewal years (Year 1, 3, 5)
- Create Workflow B: triggers on Closed Won for "even" renewal years (Year 2, 4, 6)
- Use "Renewal Year" property to route correctly
- Step-by-step setup with screenshots
- Pros: No third-party tools needed
- Cons: Fragile, requires careful property management, naming gets complex
- Link → C7: "Set up the Renewal Year property"

**H2: Solution 2 — Boolean Toggle Pattern (Native HubSpot)**
- Add "Renewal Created" boolean property (default: No)
- Workflow triggers on Closed Won AND "Renewal Created" = No
- After creating next renewal deal, set "Renewal Created" = Yes on the original
- After 31-minute delay, set "Renewal Created" = No on the NEW deal (priming it for next cycle)
- Step-by-step with screenshots
- Pros: Simpler than dual-workflow, scales to any year
- Cons: Timing-sensitive, delay can cause edge cases

**H2: Solution 3 — Custom "Renewal Stage" Property Per Year**
- Create a dropdown: "Year 1 Renewal", "Year 2 Renewal", etc.
- Each workflow targets a specific value
- Format Data action increments the value
- Pros: Clear audit trail
- Cons: Requires new dropdown value for each year (doesn't truly scale infinitely)

**H2: Solution 4 — Third-Party Tools (When Native Isn't Enough)**
- **CloneNer:** CRM card with auto-rules, dynamic property tokens, copies line items (solves the line item gap too)
- **Zapier/Make:** Multi-step automation with HubSpot API, no re-enrollment limits
- **Custom API integration:** For complex multi-product, variable-term contracts
- When to use each: team size, contract complexity, budget
- Link → C3: "Start with the foundational workflow before adding complexity"

**H2: The Line Item Problem (Bonus)**
- Why line items don't copy: workflows copy deal properties but NOT line items
- This is the #2 most-requested HubSpot Ideas feature
- Workarounds: CloneNer, Zapier with HubSpot Line Items API, manual re-entry
- Impact: incomplete renewal deals, manual work, pricing errors

**H2: Testing Your Multi-Year Automation Before Go-Live**
- Create a test deal with a close date 2 days from now
- Walk through the full chain: Closed Won → renewal created → stage progression → next renewal
- Check: correct deal name, amount, dates, associations, owner
- Common failures to watch for: missing associations, wrong pipeline, property not copied
- Link → C10: "12 Mistakes That Are Costing You Revenue"

- Create "Account Health" dropdown: Healthy, Passive, At Risk
- Manual or semi-automated based on available signals
- Automated inputs (ProfitPad model):
  - Healthy: high usage, strong NPS, minimal tickets
  - Passive: low engagement, infrequent logins
  - At Risk: 50%+ usage drop, billing issues, NPS < 6
- When this is enough vs. when you need native scoring
- Link → C2: "How health maps to pipeline stages"

**H2: Building the At-Risk Alert Workflow**
- Trigger: Account Health changes to "At Risk" on Company record
- Action 1: Notify account owner immediately (email + Slack)
- Action 2: Create task — "Review at-risk account within 24 hours"
- Action 3: Weekly digest to CS leadership of all at-risk accounts
- Action 4: Enroll contact in "Save" sequence
- Action 5: If renewal within 90 days → escalate priority

**H2: Building a Churn Reason Taxonomy**
- Why "Lost to competitor" isn't specific enough

- Quarterly churn analysis: how to slice the data
- Link → C5: "Building churn dashboards"

**H2: Proactive Signals Beyond Health Scores**
- Open support tickets during renewal window → pause renewal outreach (timing collision prevention)
- Leadership/champion changes → relationship risk alert
- Product usage decline trend → early warning (3+ months before renewal)
- QBR coverage tracking: low coverage correlates with higher churn (ProfitPad)
